README for impatient developers

Firstmate state, in 60 seconds.

Workers write facts to $FM_HOME/state/. The watcher reads them, decides whether to stay quiet or wake the first mate, and the first mate reads the queue before acting.

The important distinction: <id>.status is history. Current state is calculated from stronger evidence.

01 / the whole flow

Write → read → decide → wake → acknowledge

No model turn is spent for routine activity. Only actionable or uncertain situations reach the wake queue.

Worker runs

Crewmate works in its session and worktree.

Records are written

Status, turn-end, and busy signals land on disk.

Watcher reads

It checks new bytes, signatures, panes, and liveness.

Queue or absorb

Busy noise is absorbed. Actionable or unknown events are queued.

First mate acts

It drains, investigates, talks to the captain, then acknowledges.

03 / do not mix these up

Three kinds of state

The same worker can be “idle” as an activity signal and still be “parked” as a task state.

current crew state

working · parked · done · blocked · paused · failed · unknown

Computed by fm-crew-state.sh from run steps, remote endpoints, busy signals, and recognized status events. It is read-only; it is not one file.

activity signal

busy · idle · unknown

Written by the adapter contract in .busy-state. “Idle” means not busy now—not that the task is complete. Missing or untrusted evidence stays unknown.

wake event

signal · stale · check · heartbeat

These are notifications for the first mate. They are not crew states. A queued event remains until it is handled and acknowledged.

04 / operating rules

The five rules

These rules explain most of the watcher’s behavior.

Status is a log, not a database field.The last line can be old; use the current-state reader for “what is happening now?”
Unknown is not idle.Broken, stale, malformed, or unverified evidence is surfaced instead of guessed away.
Routine busy activity is absorbed.A no-verb note does not wake the model when positive evidence says the crew is working.
Stale output gets a second opinion.The watcher checks run state, busy state, pause state, and turn-end timing before escalating.
Read first; acknowledge last.The wake queue is drained before new work, and rows are removed only after handling completes.
current-state reader

If you need one command: bin/fm-crew-state.sh <id>

It reads the available evidence and prints one answer like state: working · source: run-step · detail: .... It does not write anything. If it cannot prove the answer, it prints unknown.
